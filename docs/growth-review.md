# 育成面談・人事考課（結いナビ）

> 2026-11-19 作り直し。別システム「結いナビ」(ブラウザ保存のみの試作) の **画面をデザインごとそのまま** CrossShift に移植した。
> 元のプログラム: `yui-navi_引き継ぎ.zip` (リポジトリには入れない)。移植先は `src/yui/` (画面) と `src/lib/yui/` (保存・権限)。
> 同日の最初の版 (結いナビ本体なしで作った仮の画面 `/admin/growth`・`/me/team`・`/me/growth`) は廃止した。

## 1. 目的

- 職員一人ひとりの成長を STEP1〜5 で見える化し、半期ごとの面談と人事考課を記録する。
- 結いナビの課題 (1 台の PC にしかデータが残らない / 名前を選ぶだけでログインできる / 職員の二重管理 /
  担当外の職員が見える) を、CrossShift の DB・ログイン・従業員マスタで解消する。

## 2. 入口と役割

画面は `/growth` 以下 (結いナビのパスの前に `/growth` を付けたもの。例 `/growth/president/home`)。
結いナビの「モード切替（開発用）」は「CrossShift に戻る」に置き換えた。

| 結いナビ | CrossShift のログイン                                                    | 入口                                     |
| -------- | ------------------------------------------------------------------------ | ---------------------------------------- |
| 社長     | 管理者 (`admin`)                                                         | 管理画面サイドバー「面談・考課」         |
| 管理者   | `users.role = manager`、または結いナビの管理者マスターで管理者にした職員 | 従業員ホーム「担当職員の面談・考課」     |
| 職員     | 従業員 (`employee`)                                                      | 従業員ホーム「わたしの成長・面談シート」 |

- 管理者が見られる・直せるのは **担当 (職員の担当管理者 = 自分) の職員だけ**。社長の確認 (処遇) は見られない。
- 職員は自分の分だけ。社長の確認は本人向けの項目 (人材ポテンシャル・次に任せる業務・育成方針・社長コメント) だけ渡す
  (結いナビの職員ホームに出ていたもの)。
- **社長はサイドバーの「モード切替」で管理者・職員の画面も開ける** (結いナビの開発用モード切替を社長だけに残したもの)。
  管理者モード / 職員モードでは、表示する管理者・職員を選び、その人の立場の画面を出す (上部に「社長が表示中」)。
  その画面で保存した内容は社長の権限で保存される。CrossShift のサイドバーから社長の画面を開くと社長モードに戻る。
- 画面を開いたとき、サーバーが「見てよい範囲」だけを渡す。保存はサーバーで毎回、ログイン中の人と DB 上の担当関係を確かめる
  (`src/lib/yui/access.ts`、テストあり)。

## 3. 職員 = 従業員マスタ

- 結いナビの職員一覧は CrossShift の従業員 (退職者を含む) + 従業員に紐づかない社長アカウント。
- **氏名・フリガナ・勤次郎コード (= 社員番号)・入社日・在籍/退職** は従業員マスタが正。結いナビの画面で直すと従業員マスタに書き戻す。
- **部署・兼務・主職種・職位・雇用形態 (夜勤専従を含む結いナビの区分)・資格・成長STEP・担当管理者・メモ** は結いナビ側だけで持つ。
  未設定なら従業員マスタ (拠点・職種・雇用形態) から初期値を作り、初期値と同じ値は保存しない (CrossShift 側の変更に追従させる)。
- 結いナビの「職員追加」(管理者) は従業員マスタに新しい従業員を作る。勤次郎コードが既存の社員番号と重なるとエラー。
  拠点は部署名が拠点名と合えば付ける。ログイン ID は従来どおり従業員画面で発行する。
- 管理者マスターの「管理者を追加」に **「職員から選ぶ」** を足した (同じ人を二重に登録しないため)。
  選ぶとその職員を管理者にする。管理者を「無効」にすると管理者から外れて職員に戻る。

## 4. 評価期間

- 結いナビでは期間を画面から増やせなかったため、社長の「設定 → 評価期間」(`/growth/president/settings/periods`) を足した。
  期間の追加・いまの期間の切り替え・開始/終了日の変更ができる (名前は記録との結びつきに使うので変えない)。
- 最初の期間「2026年 下期」(2026-10-01〜2027-03-31) はマイグレーションで入れた。

## 5. データ

[database-design.md §2.24](database-design.md) 参照。記録は結いナビの型 (`src/yui/types`) のまま JSON で保存する。

## 6. 移植で変えたところ (結いナビとの差分)

- ログイン画面 → CrossShift のログイン。モード切替 (開発用) → 社長だけが使えるモード切替 + 「CrossShift に戻る」
- 保存先 localStorage → DB (`src/yui/storage.ts` が同じ関数名で DB 版に差し替え)
- react-router → Next.js (`src/yui/router.tsx` が Link 等を置き換え)
- ID は UUID
- 設定に「評価期間」、管理者マスターに「職員から選ぶ」を追加
- Tailwind v3 → v4 の違いは `globals.css` の `.yui` の中で吸収 (色・影・角丸・フォントは元の設定のまま)
