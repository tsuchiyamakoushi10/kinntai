# 育成面談・人事考課（旧「結いナビ」の取り込み）

> 2026-11-19 追加。別システム「結いナビ」(ブラウザ保存のみの試作) の機能を kinntai に取り込む。
> 元資料: 結いナビ システム概要 / 技術引き継ぎ資料 (2026-11-10)。
> 結いナビのプログラム本体はまだ受け取っていないため、**STEP ごとの評価の目安・選択肢の一覧は仮の文言**
> (`src/lib/growth/constants.ts` の `TODO(結いナビ本体)` 箇所)。本体を受け取ったら差し替える。

## 1. 目的

- 職員一人ひとりの成長を STEP1〜5 で見える化し、半期ごとの面談と人事考課を記録する。
- 結いナビの課題 (1 台の PC にしかデータが残らない / 社員番号だけでログインできる / 職員の二重管理 /
  URL を打てば担当外の職員が見える) を、kinntai の DB・ログイン・従業員マスタで解消する。

## 2. 役割

| 結いナビ | kinntai                            | できること                                                                   |
| -------- | ---------------------------------- | ---------------------------------------------------------------------------- |
| 職員     | 従業員 (`employee`)                | 自分の STEP・今期の期待目標を見る。面談シートを書いて出す                    |
| 管理者   | **部署の管理者 (`manager`、新設)** | 職員としての機能 + 担当職員のカルテ・面談記録・一次考課                      |
| 社長     | 管理者 (`admin`)                   | 全職員の上記すべて + 最終考課・面談確認 (処遇判断)・評価期間・担当の割り当て |

- 「部署の管理者」はログイン種別 `users.role = manager`。従業員画面 (`/me`) をそのまま使え、
  ホームに「担当職員の面談・考課」が出る。
- 部署の管理者が見られるのは **担当に割り当てられた職員だけ** (サーバー側で毎回確認する)。
- 担当の割り当て・部署の管理者にする / 戻すは社長 (admin) が設定画面で行う。
- 役割は毎リクエスト DB から読む (付け替え直後でもログインし直し不要)。
- 従業員の追加・基本情報の編集は従来どおり「従業員」画面 (admin) で行う。結いナビにあった
  管理者による職員追加・編集は、二重管理を避けるため取り込まない。
- シフト用の `employees.is_manager` (施設管理者フラグ) とは別物。

## 3. 流れ (半期ごと)

```
① 職員が面談シートを書いて出す              (/me/growth)
② 部署の管理者が面談をして記録する          (/me/team/[職員]/interview)
③ 部署の管理者が一次考課を付けて社長へ出す  (/me/team/[職員]/assessment)
④ 社長が最終考課を決める                    (/admin/growth/staff/[職員]/final)
⑤ 社長が面談確認・育成方針・処遇を記録する  (/admin/growth/staff/[職員]/review)
```

- 担当の管理者がいない職員 (部署の管理者本人など) は、社長が ②③ も直接入力できる。
- 面談シートは担当者の面談記録が「完了」になるまで本人が直せる。
- 一次考課は「下書き」と「社長へ提出」。提出後も社長が最終考課を確定するまでは管理者が直せる。
- 最終考課は一次考課を初期値として表示し、変えた項目には理由を書く。

## 4. 評価

- 5 項目 × S / A / B / C、それぞれ根拠 (具体的な行動・事実) を書く。
  利用者本位の行動 / 接遇 / チームワーク / 主体性・改善 / 責任感
- STEP ごと × 項目ごとの「A 評価の目安」(25 通り) を入力画面に出す。**文言は仮**。
- 結いナビの面談記録にあった「旧 5 項目評価」は一次考課と重複するため取り込まない。

## 5. 評価期間

- 社長が設定画面で追加・編集・削除できる (結いナビでは開発者しか追加できなかった)。
- 「いまの期間」は 1 つだけ。各記録は期間 ID で結びつける (結いナビの `'2026-上期'` 文字列変換は廃止)。
- 記録が 1 件でもある期間は削除できない (先に記録を消す)。

## 6. 処遇

- 前期の基本給・賞与は、前の期間の面談確認の「今期」の値を初期値にする。前の記録が無いときは
  従業員マスタの基本給を使う。
- 昇給の実務 (通知書・賃金の書き換え) は既存の「昇給通知」で行う。ここでは判断の記録のみ。

## 7. 画面

| ID     | 画面               | URL                                                     | 使う人        |
| ------ | ------------------ | ------------------------------------------------------- | ------------- |
| S-E-14 | 面談シート         | `/me/growth`                                            | 職員          |
| S-E-15 | 担当職員一覧       | `/me/team`                                              | 部署の管理者  |
| S-E-16 | 職員カルテ         | `/me/team/[id]` ・ `/admin/growth/staff/[id]`           | 管理者 / 社長 |
| S-E-17 | 面談記録           | `.../interview`                                         | 管理者 / 社長 |
| S-E-18 | 一次考課           | `.../assessment`                                        | 管理者 / 社長 |
| S-A-42 | 面談・考課の状況   | `/admin/growth`                                         | 社長          |
| S-A-43 | 人材ダッシュボード | `/admin/growth/talent`                                  | 社長          |
| S-A-44 | 最終考課           | `/admin/growth/staff/[id]/final`                        | 社長          |
| S-A-45 | 面談確認・処遇     | `/admin/growth/staff/[id]/review`                       | 社長          |
| S-A-46 | 面談・考課の設定   | `/admin/growth/settings` (評価期間・部署の管理者・担当) | 社長          |

追加・修正・削除はすべての記録 (期間、STEP の履歴、期待目標、面談シート、面談記録、一次考課、
最終考課、面談確認) でできる。削除は確認を出す。
