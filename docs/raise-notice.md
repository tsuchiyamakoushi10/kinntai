# 昇給通知書

賃金を上げるときに、本人へ渡す「昇給通知書」(A4・1 枚、下部に受領書) を作る。
労働条件通知書 ([labor-notice.md](labor-notice.md)) と同じく、社長の入力を 1 回で済ませるため、発行と同時に賃金データも書き換える。

## 1. 発行で起きること

1. `raise_notices` に 1 行作る。書面の表示値は `snapshot` (`RaiseView`) に保存し、後でマスタが変わっても同じ書面を印刷できる。
2. 最新の雇用契約 (最後に発行した労働条件通知書の契約、無ければ開始日が最も新しい契約) の `wage_type` / `wage_amount` を変更後の基本の金額にする。
3. 従業員の `base_wage_type` / `base_wage_amount` を同じ値にする。
4. 次に「更新版」「無期の通知書」を作るとき、前回の通知書より後に出した昇給通知の変更後の金額を賃金欄に入れる (`applyRaiseToWage`)。

- 新しい金額の開始日が先の日付でも、データは発行した時点で書き換える (給与計算はこのアプリでは行わないため)。
- 番号は振らない。間違えたら削除して作り直す。削除しても書き換えた賃金は戻さない (画面で注意を出す)。

## 2. 金額の行

| key           | 書面の項目                | 単位               | 次の労働条件通知書へ                 |
| ------------- | ------------------------- | ------------------ | ------------------------------------ |
| BASE          | 基本給 / 時給 / 夜勤 1 回 | 月額 / 時給 / 1 回 | `baseYen` / `hourlyYen` / `totalYen` |
| QUALIFICATION | 資格手当（資格名）        | 月額               | `qualificationAllowanceYen`          |
| ALLOWANCE     | 人ごとの手当 (名前は種類) | 月額               | `allowances` の同じ `code` の金額    |
| OTHER         | 社長が名前を付けた手当    | 月額               | 引き継がない (書面のみ)              |

- ALLOWANCE は労働条件通知書の「人ごとの手当」([labor-notice.md](labor-notice.md) §2.2)。その区分に載せる使用中の種類はすべて行に出し (0 円でも昇給できるように)、使わない種類でも金額が残っていれば出す。行は `code` で手当の種類を指す。2026-11-10 より前の昇給通知 (key が `MANAGER` / `COUNSELOR`) は読み込み時に ALLOWANCE + 同名の `code` へ読み替える。
- 「今の金額」は、新しい方から 前回の昇給通知の変更後 → 最後の労働条件通知書の賃金 → 従業員データの基本給 の順に取る (画面に出どころを表示)。どれも無ければ 0 円から手入力。
- 変更前も変更後も 0 円の行は書面に出さない。月給のときだけ月額の合計行を出す。
- 金額が 1 つも変わっていない、変更後の基本の金額が 0、追加した手当に名前が無い、はエラー。下がった行は警告 (発行はできる)。
- ロジックは `src/lib/raise-notice/` (テスト `tests/raise-notice/`)。

## 3. 書面

- 発行日、宛名 (〇〇 殿)、会社名・代表者、「下記のとおり賃金を改定（昇給）」、新しい金額の開始日、勤務先、項目ごとの 変更前 / 変更後 / 増減 の表、ひとこと (任意)。
- 下部に切り取り線と受領書 (受け取った日・氏名（自署）・印)。
- 印刷は労働条件通知書と同じく、ブラウザの印刷画面 (`/admin/raise-notices/[id]/print`)。

## 4. 画面

| ID     | 画面          | 内容                                                                               |
| ------ | ------------- | ---------------------------------------------------------------------------------- |
| S-A-39 | 昇給通知 一覧 | 「作業中」「完了フォルダ」のタブ。完了フォルダへ移す / 戻す                        |
| S-A-40 | 昇給通知 作成 | 従業員 → 新しい金額 (今の金額は自動で入る) → 日付 → ひとこと。右に A4 プレビュー   |
| S-A-41 | 昇給通知 詳細 | 印刷、署名済み受領書の登録 (→ 自動で完了フォルダ)、完了フォルダへ移す / 戻す、削除 |

労働条件通知書の詳細 (S-A-32) から「昇給通知を作る」で、その人を選んだ状態で開ける。

## 5. テーブル `raise_notices`

```
id                  uuid PK
employee_id         uuid FK employees
office_id           uuid FK offices      (最後の労働条件通知書の勤務先、無ければ従業員の所属)
contract_id         uuid FK employment_contracts null (賃金を書き換えた契約)
issued_on           date                 (通知する日)
effective_on        date                 (新しい金額の開始日)
snapshot            jsonb                (RaiseView)
signed_at           timestamptz null
signed_document_id  uuid FK employee_documents null (受領書のスキャン。書類種別は「その他」)
archived_at         timestamptz null     (完了フォルダへ移した日時)
created_by          uuid FK users
created_at, updated_at
```

tenant_id はマルチテナント化時に追加する。
